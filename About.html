01 — The Story

How I got here

I started building for the web because I wanted to understand how the things I used every day actually worked. That curiosity turned into a habit — and the habit turned into a craft.

These days I build websites, front-end interfaces and Java web applications. I care about the parts users don't see: clean markup, sensible structure, fast load times, and code that the next person can actually read. I'd rather write something simple that works than something clever that needs explaining.

I work from South Africa, but most of my collaboration happens online — which means I'm used to working across time zones, communicating in writing, and keeping projects moving without needing to be in the same room.

When I'm not coding, I'm usually reading about design systems, tinkering with side projects, or figuring out why something that should work doesn't. That last one is most of the job, honestly.

04 — How I Work

What I care about

01

Clarity over cleverness

Simple code that someone else can read beats clever code that only I understand. I'd rather be clear than impressive.

02

Honest timelines

I'll tell you how long something will actually take — not how long you want to hear. And if I can't meet a deadline, you'll know early.

03

Details matter

The extra care in spacing, the correct semantic tag, the load time — these are the things that make a site feel good, even if nobody notices why.

04

Plain language

No jargon, no buzzwords, no "synergistic solutions". If I can't explain something simply, I probably don't understand it well enough yet.

05

Built to last

Code that's easy to maintain and extend is worth more than code that's fast to write. I build with the next person in mind.

06

People first

The person using the site matters more than the framework it's built with. Everything else is just how we get there.

Want to work together?

I'm always happy to talk about a project, a role, or an idea that's still taking shape. No pressure — just a conversation.
